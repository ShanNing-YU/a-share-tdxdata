# 通达信「下载今日日线」批量接口逆向指南

> 2026-09-15 编写。目标：逆向官方批量日线下载接口（代替单只 SNAP 循环）。
> 已在手的数据：`captures/tdx_capture.pcapng`（**收市后**抓包，含批量请求+响应样本，704 只 → 54779B 文本）。

## 为什么值得逆
- 单只 SNAP：43 连接并发 ≈ 12-15 分钟全市场（已可用，见 pool2.py）
- 批量日线：真实客户端收市后一次下载全市场（704 只/批），**几百只/秒级**，远快于单只
- 但批量请求疑似需要 0c01 登录会话（身份校验）→ 目前重放 0B，需真实会话观察

## 一、完成品的两种形态（待验证哪条通）

### A. 直接用现有抓包逆向（0 成本，先做）
`analysis_round2.md` 已记录：tdx_capture.pcapng 的 49567 流 = 批量快照请求（明文 code 列表）+ 7788 段响应 → zlib 解压 54779B 竖线文本（`0|000001|T1001|||`、`1|513500|1|20260902|20260915`）。
→ 请求格式已经能逐字节抄出来（74B 批量：`000000000000 c002 c002 1000 6400 [market] [codes...]`）。
→ 卡点：午休重放 0B。**待出口 IP 冷却 + 盘中/盘后重试**：若通 → 批量日线直接用；若 0B → 需要新抓包（路径 B）。

### B. 收市后新抓「下载今日日线」（10 分钟，最干净）
批量请求可能依赖 0c01 会话，需要真实客户端的「登录态 + 下载动作」才能拿到**无歧义**的请求-响应对。

## 二、用户操作步骤（收市后 15:00+，需要 10 分钟）

1. **完全关闭通达信客户端**（任务管理器确认没有 TdxW.exe 残留）
2. 管理员 PowerShell 开始抓包：
   ```
   pktmon start --capture -f C:\Users\YUZQ\Desktop\tdx_dl.etl
   ```
3. 打开通达信客户端
4. 等它弹「是否下载今日日线数据」→ **点确定/是**
5. **不要做其他操作**，等下载完成（进度条走完）
6. 停止抓包：
   ```
   pktmon stop
   pktmon etl2pcap C:\Users\YUZQ\Desktop\tdx_dl.etl -o C:\Users\YUZQ\Desktop\tdx_dl.pcapng
   ```
7. 把 `tdx_dl.pcapng` 放到 `~/workspace/tdx-proto-re/captures/`，告诉我「抓好了」

## 三、助手拿到新抓包后的分析流程

1. **找批量请求**：扫描 7709 连接里含大量 6 位 code 的请求段
   （对比 `find_batch_reqs.py` 的 444B/6-code 分页格式，找更大的批量请求）
2. **对照 0c01 会话时序**：抓包里有 0c01 加密登录（e538...）→ 记录连接建立后的完整请求序
   与单只 SNAP 对比 → 确认批量请求是否只在 0c01 后有效
3. **解析响应流**（沿用 `ZlibStreamDecoder`）：
   - 帧头 16B 剥离 → zlib 跨段解压 → 竖线文本（`1|code|日期|价格`）或差分 K 线字节
   - 确认字段：日期区间、OHLC、成交量、复权
4. **重放验证**：
   - 完整复制「0c01 → 0c02 → 0c03 → 批量请求」序列打服务器
   - 若 0c01 必须真实客户端 → 记录结论：批量接口只能在**用户开着客户端时**由客户端做，
     tdxdata 则继续用单只 SNAP 兜底
5. **定稿**：把批量格式写进 `tdxdata/commands/bars.py`（替代 0c07 空壳）

## 四、已确认的批量格式线索（来自 tdx_capture.pcapng）

```
  000000000000 c002 c002 1000 6400 00 [code6 × N 连排]    (000001/000002/000006...)
沪市批量（74B 样例）:

分页列表（0c0a-0c19 26B）:
  0c0a 186e 0001 1000 1000 4d04 [offset 4B] 00 [4006 0000] → 板块/指数列表 zlib 59202B
```
