# 通达信协议逆向 — 第二轮抓包分析（2026-09-14 晚）

## 🎯 重大进展：协议可逆，格式已确认
1. **服务器响应** = 16B 头（`b1cb7400|1c02|1894|...`）+ **zlib 压缩数据**（标准 deflate，wbits=15 解压成功）
2. **解压后** = 老式差分价格编码（老 pytdx 同款：`3a02 b202 0c03 8403...` 递增差分）+ 日期字节（`00322835011b4a01...`）+ ASCII code 头（`303030303136`="000016"）
3. **请求** = 命令族 0c01-0c09（K线/快照/指数）；长请求含**明文 ASCII code**（`0c07...000002`），短请求（13B）为订阅/轮询
4. **版本标识变了**：老 pytdx `0x01016408` → 新客户端 `0x01187b00`（服务器校验，老库被拒）

## 已逆出的新格式细节
- 响应头 16B：`b1cb7400`(seq) + 响应命令（0c01=空响应 / 1c02=有数据）+ 关联参数
- K 线数据：zlib(deflate) 压缩，解压后差分价格 float/整数编码 + 日期
- 样例解压（79B）：`00 ea 07...` 差分价格序列 `3a02 b202 0c03 8403`（重复 = 多周期） + 日期
- 上证指数等关注列表：明文请求 `0c01002a...` 含 `999999`/`000680`/`399006` + 价格×10000

## 未解之谜
- 收盘后客户端**不拉完整历史 K 线**（79B 只有少量记录）→ 完整 800 条日线需**盘中抓包**验证
- 0c02 短请求(13B) 不含 code，服务器如何知道要哪只股票？（可能关联「当前视图」或长请求建立的上下文）
- 加密的 74B K线请求（`0c01187b...` e538 开头）用途未明——可能带 code 的 K线拉取走这个（加密），而明文 code 的是快照/指数
